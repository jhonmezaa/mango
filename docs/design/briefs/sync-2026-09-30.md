# Ajustes para Claude Design (2026-09-30)

Contexto del proyecto **Mango** para alinear el diseño con lo que ya existe. Solo describe hechos, reglas y estados.

## 1. "Reporta a" y Org Chart

- El Marketplace muestra "Reporta a" y "Rol" en el panel de detalle del agente (sección «organización»). La vista de lista muestra el rol.
- El Org Chart arma el árbol con esos mismos datos.
- El Agent Builder no tiene ningún campo para definirlos. Al publicar un agente nuevo, queda bajo «Platform Admin» sin que nadie lo elija. La revisión y el diff de versiones tampoco incluyen supervisor ni rol.
- El Org Chart incluye delegación entre agentes vía A2A: KPIs de delegaciones, «Delegaciones recientes» y el modal «Delegar vía A2A». Hoy no existe backend para la jerarquía de agentes ni para la delegación, y no hay ninguna acción de permiso para delegar.

## 2. Nombre del agente

- El prototipo usa «FinOps Navigator» en el sidebar, la cabecera y el hero del chat, el historial, el placeholder y Presupuestos › Por agente.
- El agente real se llama **«FinOps»** (así lo registran el backend y la configuración del agente). La web ya usa «FinOps» en todas esas vistas, salvo en el carrusel del login.

## 3. Formato de las respuestas del chat

El diseño define dos estilos distintos para el Markdown del agente:

- `markdown.js` (estilos inline, que son los que se ven en el prototipo):
  - tablas al 100 % de ancho y a 12 px, solo con bordes horizontales;
  - cabecera sin fondo;
  - las dos últimas columnas siempre alineadas a la derecha;
  - títulos de 18/15/13 px.
- `styles.css`: tablas con rejilla completa y cabecera con fondo.

Hace falta que el diseño defina cuál es el correcto.

## 4. Lo que ya existe en la web y no está en el diseño

**Chat:**
- Los enlaces que escribe el agente no se abren directo: muestran el diálogo «Abrir enlace externo» con la URL completa.
- Las imágenes del Markdown del agente se reemplazan por «[Imagen bloqueada]». El contenido que genera el modelo no es confiable.
- Sugerencias del agente FinOps: «Gasto del mes», «Top 5 servicios», «Pronóstico de fin de mes» y «Anomalías de la semana». El agente no hace rightsizing.
- Descripción del agente, capacidades y «1 MCP server»: vienen de lo que el agente consulta de verdad (Costos y uso, Áreas y OUs, Pronósticos, Anomalías, Savings Plans).
- Estados del historial y de la conversación:
  - carga con esqueleto;
  - vacío: «Aún no tienes conversaciones.»;
  - error del historial: «No se pudo cargar el historial.»;
  - error de la conversación: «No se pudo cargar la conversación», con «Reintentar» y «Nueva conversación».
- La duración de las tools solo aparece si se midió durante la respuesta. En las conversaciones ya cargadas no se muestra.

**Login:**
- El carrusel tiene un botón «Pausar» / «Reanudar». Además se detiene con el foco y con «reducir movimiento».
- Después de verificar el correo, el usuario pasa directo a configurar el MFA, sin volver a iniciar sesión.

**Sistema:**
- Página 404: «Página no encontrada», «La dirección no existe o ya no está disponible.» y «Volver al chat».
- La pantalla de error inesperado muestra solo el código `RENDER_ERROR`, nunca el mensaje interno del error.

**Ajustes › Conectividad:**
- Si falla la API de la prueba, se muestra el banner «No se pudo ejecutar la prueba».
