## 2. Lo que el producto hace distinto

### 2.1 Insignia corta de «FinOps central» sin administrador

El diseño tiene `owner` → «Creador» y `central` → «Usuario». La API registra con el evento solo el rol (`finops-central` o `bu-lead`) y si era administrador; no dice si la persona es creadora de agentes. Para «FinOps central» sin administrador el producto muestra **«FinOps central»** completo en la insignia, en vez de afirmar «Creador» o «Usuario» sin saberlo. Los otros tres casos usan la insignia corta: «Admin» (los dos administradores) y «Usuario» (líder de área).

Pedido: un texto corto para ese caso que no dependa de saber si crea agentes (por ejemplo «Central»), o confirmar que se queda «FinOps central».

### 2.2 Actores «Agente» y «Sistema»

En el producto el actor de una consulta del chat es la persona que preguntó (el agente es el recurso), y un evento sin actor se muestra «Sistema» sin insignia. Las insignias «Agente» y «Sistema» del diseño no llegan a verse.

### 2.3 Cuándo se juntan «solicitado» y su resultado

El producto junta los dos eventos con la misma regla del diseño (misma acción, recurso y actor; el resultado menos de dos minutos después). Diferencia: Auditoría se carga por páginas. Si el «solicitado» quedó en una página que aún no se cargó, el resultado se ve solo, sin la fila «Solicitado» en el panel; al pulsar «Mostrar más» y llegar el otro evento, se juntan. Nunca se oculta un «solicitado» cuyo resultado no esté cargado.

### 2.4 Rechazo al aprobar: «demasiados grupos»

La API también puede rechazar una aprobación porque la persona **ya tiene el máximo de grupos**. El diseño no tiene texto para ese caso y el producto muestra el genérico «No se pudo completar la acción. Inténtalo de nuevo.», que invita a reintentar algo que no va a funcionar. Pedido: un texto, por ejemplo «No se pudo aprobar {id}: la persona ya tiene el máximo de grupos. Quítale uno antes; el cambio sigue pendiente.»

### 2.5 «Ya no está en el directorio» en «Cambios de personas»

No está implementado. La lista de cambios que entrega la API no dice si la persona sigue en el directorio, y la pantalla solo conoce la página del directorio que tiene cargada (20 personas), así que no puede saberlo. Queda pendiente del producto que la API lo informe; el texto del diseño se usará tal cual.

### 2.6 Invitar: detalles del rechazo del servidor

- Un correo con caracteres que el directorio no admite lo rechaza la API como formato inválido. Ese caso se muestra bajo el campo («Escribe un correo válido»), no al pie.
- Mientras se escribe un correo público, la ayuda dice «Dominio externo: se invita como persona de otra empresa y queda así en Auditoría.», porque la pantalla no sabe que es público hasta enviar (ya anotado en `sync-2026-10-03j.md`, 3.6).
- El mensaje al pie se borra al volver a escribir en el campo.
